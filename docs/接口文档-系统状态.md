# 接口文档-系统状态

日期：2026-09-27

## 基础信息

- 模块名称：系统状态
- 当前阶段：第十阶段，IPv4/IPv6 双栈局域网 HTTP 服务、Bearer Token 访问密码认证和硬件状态采集
- 默认端口：`17890`
- 默认本机访问地址：`http://localhost:17890/`
- 本机 IPv6 回环访问地址：`http://[::1]:17890/`
- 局域网 IPv4 访问地址：`http://<本机局域网IPv4>:17890/`
- 局域网 IPv6 访问地址：`http://[<本机局域网IPv6>]:17890/`
- 当前认证：可选。设置页开启访问密码后，需要先调用 `POST /api/auth/login` 获取 token，后续受保护接口通过 `Authorization: Bearer <token>` 访问。

说明：本阶段使用轻量 `TcpListener` 服务，优先通过 `IPAddress.IPv6Any` 和 `Socket.DualMode=true` 创建 IPv4/IPv6 双栈监听；如果当前系统不支持 IPv6 双栈，会自动回退到 IPv4 的 `IPAddress.Any` 监听。IPv6 地址作为 URL 主机名时必须使用方括号，例如 `http://[2001:db8::1234]:17890/`。浏览器或局域网设备访问前，需要确认 Windows 防火墙没有拦截该端口。

## 请求处理与采集边界（2026-09-27）

JSON 正文使用严格 UTF-8，`Content-Length` 按字节计数，支持中文与 Emoji。请求头最大 16 KB，正文最大 64 KB；单连接处理截止时间为 10 秒，最多 16 个活动连接，超过并发上限时新连接关闭。当前不支持 chunked 正文，客户端应发送 Content-Length。

非法长度、重复请求头、截断正文、无效 UTF-8 或不支持的编码返回 HTTP 400；正文超限返回 413；请求头超限返回 431。上述解析错误 JSON 为 `{"error":"invalidRequest"}`。连接超时/服务停止会关闭连接，客户端应处理网络错误。

`GET /api/status` 使用串行采集的 1 秒缓存，多客户端在同一周期共享快照。现有路由、字段和 token 规则保持不变。温度源改为本机受限 IPC 的管理员辅助进程，主 HTTP 进程不提权；标准用户用另一管理员账户凭据的授权不支持。

## 获取认证状态

```http
GET /api/auth/state
```

用途：获取当前是否启用了访问密码。这个接口公开访问，不返回密码哈希。

响应示例：

```json
{
  "passwordEnabled": true
}
```

## 登录

```http
POST /api/auth/login
```

用途：校验访问密码并获取临时 token。这个接口公开访问。

请求头：

```http
Content-Type: application/json
```

请求示例：

```json
{
  "password": "your-password"
}
```

响应示例：

```json
{
  "passwordEnabled": true,
  "token": "TOKEN_VALUE",
  "expiresAt": "2026-06-02T00:00:00+08:00"
}
```

说明：

- 新密码保存带随机盐的 PBKDF2-SHA256（600000 次）派生值，不保存明文密码；已有 SHA-256 哈希仍可验证，重新设置密码后升级。
- 登录成功后 token 当前有效期为 12 小时。
- 修改密码或重新应用系统状态设置后，旧 token 会失效。
- 密码未启用时，登录接口返回空 token，其他接口保持开放访问。
- 如果旧配置里出现 `passwordEnabled=true` 但 `passwordHash` 为空，程序会归一化为密码未启用，避免用户无法登录。

## 获取系统状态

```http
GET /api/status
```

用途：获取当前系统状态快照，用于后续网页仪表盘刷新卡片数据。

请求参数：无。

认证：启用访问密码后需要请求头：

```http
Authorization: Bearer <token>
```

响应头：

```http
Content-Type: application/json; charset=utf-8
Access-Control-Allow-Origin: *
```

响应示例：

```json
{
  "timestamp": "2026-06-01T10:30:00",
  "downloadSpeed": {
    "status": "Available",
    "displayText": "1.0 KB/s",
    "numericValue": 0,
    "unit": "B/s"
  },
  "uploadSpeed": {
    "status": "Available",
    "displayText": "2.0 KB/s",
    "numericValue": 0,
    "unit": "B/s"
  },
  "cpuUsage": {
    "status": "Available",
    "displayText": "35.3%",
    "numericValue": 35.3,
    "unit": "%"
  },
  "cpuTemperature": {
    "status": "Available",
    "displayText": "61.8 °C",
    "numericValue": 61.8,
    "unit": "°C"
  },
  "gpuUsage": {
    "status": "Available",
    "displayText": "42.3%",
    "numericValue": 42.3,
    "unit": "%"
  },
  "gpuTemperature": {
    "status": "Available",
    "displayText": "70.3 °C",
    "numericValue": 70.3,
    "unit": "°C"
  },
  "memoryUsage": {
    "status": "Available",
    "displayText": "60.0% (6.0 GB / 10.0 GB)",
    "numericValue": 60,
    "unit": "%"
  }
}
```

指标对象字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `status` | string | `Available` 或 `Unavailable`。 |
| `displayText` | string | 前端可直接展示的文本。 |
| `numericValue` | number/null | 数值。不可用时为 `null`。 |
| `unit` | string | 单位，例如 `%`、`°C`、`B/s`。 |

注意：

- 当前阶段网速指标的真实数值字段还未最终稳定，`displayText` 是可靠展示字段。后续做图表或趋势线时，需要补齐上传/下载的真实 bytes/sec 数值。
- CPU 温度和 GPU 温度已经接入 `LibreHardwareMonitorLib`。CPU 温度优先读取 CPU 节点下的 `Core Average`；AMD CPU 无该值时按 `Core (Tdie)`、`Core (Tctl/Tdie)`、`Core (Tctl)` 顺序选取有效值。`0 °C` 视为无效读数，不使用 `CPU Package`、单核心温度或主板/SuperIO 温度兜底；没有有效传感器时返回 `Unavailable`。GPU 占用率优先读取 Windows `GPU Engine(*)\Utilization Percentage` 性能计数器，失败时再回退到硬件库的 GPU 负载传感器。CPU 温度这类底层传感器通常需要 Windows 管理员权限；主 EXE 为 `asInvoker` 普通权限。温度由独立管理员采集进程提供；设置中点击“授权硬件采集”完成首次 UAC 授权并注册采集任务。升级采集程序后需在设置重新点击“授权/更新采集程序”，确认 UAC 以替换原受保护进程。拒绝授权、未连接、快照超过 5 秒或硬件/驱动不支持时，对应温度字段返回 `Unavailable`。

## 服务占位首页

```http
GET /
```

用途：返回系统状态浏览器仪表盘页面。

认证：页面 HTML 本身公开返回，页面加载后会通过 `GET /api/auth/state` 判断是否需要登录。启用密码时，页面会先显示登录框，登录成功后再请求状态数据。

页面行为：

- 加载后请求 `GET /api/settings` 获取主题、刷新间隔、卡片显示开关和布局顺序。
- 按刷新间隔请求 `GET /api/status`。
- 响应式卡片展示网速、CPU、GPU、内存等指标。
- 各状态卡片使用统一高度，避免网速、内存等卡片因内容行数不同导致大小不一致。
- 支持拖拽卡片排序，并调用 `POST /api/layout` 保存布局。
- 支持网页内浅色/深色切换，并调用 `POST /api/theme` 保存主题。

## 获取仪表盘设置

```http
GET /api/settings
```

用途：获取网页仪表盘渲染需要的配置。

请求参数：无。

认证：启用访问密码后需要请求头：

```http
Authorization: Bearer <token>
```

响应示例：

```json
{
  "refreshIntervalSeconds": 1,
  "webTheme": "FollowApp",
  "effectiveTheme": "Dark",
  "cards": {
    "networkSpeedVisible": true,
    "cpuUsageVisible": true,
    "cpuTemperatureVisible": true,
    "gpuUsageVisible": true,
    "gpuTemperatureVisible": true,
    "memoryUsageVisible": true
  },
  "layout": [
    {
      "cardKey": "network",
      "order": 0
    },
    {
      "cardKey": "cpuUsage",
      "order": 1
    }
  ]
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `refreshIntervalSeconds` | number | 页面刷新间隔，单位秒。 |
| `webTheme` | string | 设置页保存的网页主题：`FollowApp`、`Light`、`Dark`。 |
| `effectiveTheme` | string | 最终生效主题：`Light` 或 `Dark`。 |
| `cards` | object | 各卡片是否显示。 |
| `layout` | array | 卡片排序信息。 |

## 保存卡片布局

```http
POST /api/layout
```

用途：保存网页仪表盘卡片排序。

请求头：

```http
Content-Type: application/json
Authorization: Bearer <token>
```

认证：启用访问密码后需要 `Authorization` 请求头。未启用访问密码时不需要。

请求示例：

```json
{
  "layout": [
    {
      "cardKey": "memory",
      "order": 0
    },
    {
      "cardKey": "network",
      "order": 1
    }
  ]
}
```

响应示例：

```json
{
  "layout": [
    {
      "cardKey": "memory",
      "order": 0
    },
    {
      "cardKey": "network",
      "order": 1
    },
    {
      "cardKey": "cpuUsage",
      "order": 2
    }
  ]
}
```

服务端会做归一化处理：

- 只接受已知卡片 key。
- 自动去重。
- 自动补齐缺失卡片。
- 重新按 `0` 开始生成连续 `order`。

已知卡片 key：

| key | 说明 |
| --- | --- |
| `network` | 网速卡片 |
| `cpuUsage` | CPU 占用率 |
| `cpuTemperature` | CPU 温度 |
| `gpuUsage` | GPU 占用率 |
| `gpuTemperature` | GPU 温度 |
| `memory` | 内存占用率 |

## 保存网页主题

```http
POST /api/theme
```

用途：保存网页仪表盘主题。

请求头：

```http
Content-Type: application/json
Authorization: Bearer <token>
```

认证：启用访问密码后需要 `Authorization` 请求头。未启用访问密码时不需要。

请求示例：

```json
{
  "webTheme": "Dark"
}
```

可选值：

| 值 | 说明 |
| --- | --- |
| `FollowApp` | 跟随软件主题 |
| `Light` | 浅色 |
| `Dark` | 深色 |

响应示例：

```json
{
  "refreshIntervalSeconds": 1,
  "webTheme": "Dark",
  "effectiveTheme": "Dark",
  "cards": {
    "networkSpeedVisible": true,
    "cpuUsageVisible": true,
    "cpuTemperatureVisible": true,
    "gpuUsageVisible": true,
    "gpuTemperatureVisible": true,
    "memoryUsageVisible": true
  },
  "layout": []
}
```

说明：网页按钮目前在 `Light` 和 `Dark` 之间切换。`FollowApp` 仍可通过设置窗口选择。

## 启停规则

HTTP 服务只有在以下两个设置同时为 `true` 时启动：

```json
{
  "systemStatus": {
    "enabled": true,
    "serverEnabled": true
  }
}
```

如果任意一个为 `false`，服务停止。

## 端口规则

- 首选端口来自 `systemStatus.preferredPort`，默认 `17890`。
- 如果首选端口被占用，服务从首选端口开始向后尝试候选端口。
- 端口超过 `65535` 后从 `1` 继续。
- 当前实现最多尝试 `20` 个候选端口。

## 当前限制

- CPU/GPU 温度已接入硬件监控库，GPU 占用率优先接入 Windows GPU Engine 性能计数器；CPU 温度通常需要 Windows 管理员权限，当前主 EXE 不请求管理员权限，硬件采集由单独授权的辅助进程提供；在不支持的硬件、驱动或权限环境下仍可能返回 `不可用`。
- GPU 占用率优先使用 Windows GPU Engine 汇总值，性能计数器不可用时回退到核心/总占用/3D/Graphics 类硬件传感器，并排除显存、视频编解码、总线等辅助负载；GPU 温度会优先使用核心/边缘温度，并排除热点、显存结温等辅助温度。
- Windows 防火墙提示或拦截需要用户手动允许。
